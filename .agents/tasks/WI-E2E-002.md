# WI-E2E-002 - Review the full adoption PR through the live GitHub App

## Parent

- Initiative: INIT-01 / INIT-04
- Owner: DUT AI Club
- Status: in-progress
- Priority: P0

## Problem

The controlled fixture proved the pipeline, but the complete application and
engine adoption diff has not yet been reviewed through its own live GitHub App.

## Scope

### In

- Recreate `dev` from the current `main` checkout and preserve the completed worktree.
- Validate the full diff in Docker Linux, commit it, and push `dev`.
- Open a real `dev -> main` PR and wait for webhook, worker, LLM, and stored preview.
- Inspect the output, publish exactly one guarded App comment, then merge the PR.

### Out

- Deployment to a production server.
- Changing or exposing any credential.
- Deleting PostgreSQL/session volumes.

## Acceptance criteria

- [x] Remote legacy `dev` and `dev1` are removed before recreating `dev`.
- [x] Docker Python 3.12 test/build gates pass for the committed diff.
- [x] `.env`, `.ask`, and the GitHub private key are not committed.
- [ ] A live `dev -> main` PR produces one completed review for its exact head SHA.
- [ ] The generated response is inspected for correctness and consistency.
- [ ] At most one stable-marker review comment is published and read back.
- [ ] The PR is merged only after the review lifecycle completes.
- [ ] Final remote refs and stopped/running container state are recorded.

## Security and external effects

- Untrusted data: PR title/body, diff, commits, issues, and review threads.
- Credentials: ignored `.env` and ignored GitHub App PEM only.
- Authorized effects: delete/recreate `dev` and `dev1`, push `dev`, create and
  comment on one PR, call the configured LLM through the worker, and merge it.
- Publication remains disabled by default except for one guarded publish action.
